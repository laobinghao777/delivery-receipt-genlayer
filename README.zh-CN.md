# 交付尺 · Delivery Receipt

一个部署在 GenLayer Bradbury Phase 2 的文本交付验收应用。先把验收标准写入合约，再锁定交付原文，最后由 GenLayer 的 AI 共识逐项判断并保存结果。

## 能做什么

- 创建包含 1–8 条标准的验收单。
- 提交文案、文档或说明文本；锁定后不可覆盖，SHA-256 与评审结果绑定。
- 每条标准给出「满足 / 未满足 / 无法证实」、原因和原文引证。
- 合约强制核对引证是否出现在交付原文中；全部标准满足才算通过。
- 只有创建者能提交或发起验收，结果不可覆盖。修改交付需创建新版本。
- 查看真实合约状态、交易状态、协议预付额度和最终余额差，导出费用 JSON。

真实链上示例已经跑通，三条验收标准全部通过。完整交互实测净消耗 **0.000256033440005644 GEN**；费用明细见 [交互费用.md](交互费用.md)。

适用场景：营销文案、客户交付说明、技术文档的条款覆盖验收。它不执行用户代码，不验证链接背后的网站功能，不做资金托管，也不是法律仲裁。

## 在这台电脑运行

已安装依赖，`pk.txt` 是本机测试钱包。私钥仅由后端读取，不发送给网页、不放入前端，也不写入日志。

```powershell
npm start
```

打开 http://127.0.0.1:4317 。也可以双击 `启动交付尺.cmd`。

这是**本机单钱包开发版**。仅监听 127.0.0.1，采用同源和随机会话校验。不要把端口映射到公网或把 pk.txt 上传到仓库。其他人使用的公开版本仍需浏览器钱包签名和独立部署，当前版本不会代替陌生人签交易。

## 验证与复现

```powershell
npm test       # 8 个合约业务规则测试；用 VM 适配器隔离 AI，不能代替共识测试
npm run check  # 核对余额、创世区块、AddressManager
npm run demo   # 服务运行时，恢复/完成示例的创建→提交→验收，避免重复创建
```

部署已经完成，地址见 `deployment.json`。新安装可复用此公开合约，无需再次部署；只有需要自己的新合约时才需要部署。`npm run deploy` 默认复用现有合约。

项目使用当前链支持的 py-genlayer 0.3 运行时。公开文档部分样例的 runner 已落后，因此使用当前已部署合约所用的 runner，并通过远程合约结构检查。

## 费用和恢复

- 交易先估算 gas；估算失败会阻止签名，禁止 SDK 回退默认 gas 后继续广播。
- 单笔最大签名成本 0.3 GEN；协议预付最多 0.2 GEN；本次开发会话净消耗达到 1 GEN 后停止发送。
- 协议预付预算不是净费用。等待最终结算和退款后，以钱包余额差记录净消耗。
- 余额差包含该钱包的全部活动。测试期间不要同时拿此钱包进行其他交互，否则无法精确归因。
- 签名时先持久化 EVM 哈希，拿到 GenLayer 交易 ID 后再跟踪最终状态；进程重启会恢复待处理交易，不自动重发。
- 首次部署有一笔费用参数错误导致的 EVM 回退，该笔费用单独保留；之后所有估算错误均未签名广播。

运行记录在 `logs/app-state.json`，共识收据在 `logs/receipt-*.json`，示例报告在 `logs/demo-result.json`。这些是本地运行数据，不应提交到源码仓库。

## 项目结构

```text
contracts/delivery_receipt.py  智能合约
web/                          中文响应式界面
scripts/runtime.mjs           SDK、本地签名、费用预算、交易恢复
scripts/server.mjs            本地 HTTP 服务与受限操作 API
scripts/demo.mjs              可复现的真实链上示例
tests/                        业务规则测试
```

## 提交贡献前

当前实现可作为开发和演示基础，尚未提交 Portal，不能保证通过贡献审核或获得积分。公开用户版、真实使用反馈、公开源码仓库和演示视频仍需进一步准备。分享源码时使用 `delivery-receipt-source.zip`；它不包含 pk.txt、运行日志和本机依赖。

提示注入仍是 AI 判断的一项限制。合约将用户输入标记为不可信数据，要求独立验证每项状态，并校验原文引证，但这些约束不等于保证 AI 判断永远正确。
